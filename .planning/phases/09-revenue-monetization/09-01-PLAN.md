# Plan 09-01: Claim Your Listing Flow

## Objective
Implement a secure, self-service mechanism for venue owners to verify their identity and initiate the sponsorship process.

## Architectural Changes

### 1. Database Schema
- Ensure `venues` table has `current_claim_status` and `claim_email`.
- Create `venue_claims` table to track claim attempts and verification tokens.

```sql
CREATE TABLE IF NOT EXISTS venue_claims (
    id BIGSERIAL PRIMARY KEY,
    venue_id BIGINT REFERENCES venues(id) NOT NULL,
    email TEXT NOT NULL,
    verification_token TEXT NOT NULL,
    verified_at TIMESTAMPTZ,
    admin_approved_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. Backend Routes
- `POST /api/venues/:id/claim`: Initiate a claim. Validates venue exists and isn't already verified. Generates token and sends email.
- `GET /api/venues/claim/verify?token=...`: Verifies the email token.
- `GET /api/admin/claims`: List pending claims for manual approval (Admin only).
- `POST /api/admin/claims/:id/approve`: Approve a claim, allowing the owner to proceed to Stripe.

### 3. Frontend Components
- **Detail Page Injection**: Add "Own this venue? Claim it now" button to the detail modal.
- **Claim Form Page**: `/claim/[slug]` — Simple form to enter business email and official name.
- **Verification Success Page**: `/claim/verified` — Landing page after email link is clicked.
