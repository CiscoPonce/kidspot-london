# Plan 09-03: Admin Revenue Dashboard & Audit Logs

## Objective
Provide administrative visibility into platform revenue, sponsorship health, and manual governance actions.

## Architectural Changes

### 1. Database Schema
- Create `audit_logs` table to track administrative actions.

```sql
CREATE TABLE IF NOT EXISTS audit_logs (
    id BIGSERIAL PRIMARY KEY,
    admin_id TEXT, -- Future proof for multi-admin
    action_type TEXT NOT NULL, -- 'claim_approved', 'tier_manual_update', 'refund_processed'
    target_id BIGINT, -- venue_id
    payload JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. Backend Routes
- `GET /api/admin/revenue/stats`: Aggregated MRR, total active subscriptions, and tier distribution.
- `GET /api/admin/audit-logs`: Paginated list of administrative actions.
- `GET /api/admin/sponsors`: Detailed list of all active sponsors with Stripe status.

### 3. Frontend Components
- **Admin Dashboard**: `/admin/revenue` — High-level metrics and charts.
- **Sponsor Management**: `/admin/sponsors` — List view with search and manual override capability.
- **Audit Viewer**: View history of actions for a specific venue.
