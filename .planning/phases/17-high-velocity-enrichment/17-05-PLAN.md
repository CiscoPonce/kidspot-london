# Plan 17-05: Asynchronous Webhooks & Deep Enrichment

## Objective
Replace the synchronous API polling mechanism with an asynchronous webhook architecture to save compute resources, and enable deep website crawling to capture owner emails for future monetization outreach.

## Proposed Changes

### 1. Webhook Endpoint
- **Location:** `backend/src/routes/admin.ts`
- **Functionality:**
  - Create a new endpoint: `POST /api/admin/webhooks/apify`
  - Secure the endpoint using a secret token checked against a new `APIFY_WEBHOOK_SECRET` env variable.
  - The endpoint will receive the `datasetId` from Apify, fetch the dataset, map the fields (including the new rich data from 17-04), and update the database.

### 2. Update `apify-enrichment.ts` (Trigger Logic)
- **Functionality:**
  - Remove the `while (status === 'RUNNING')` polling loop.
  - Modify the Apify Actor start request to include webhook configuration:
    ```json
    "webhooks": [{
      "eventTypes": ["ACTOR.RUN.SUCCEEDED"],
      "requestUrl": "https://api.kidspot.london/api/admin/webhooks/apify?token=SECRET"
    }]
    ```
  - The script now just triggers the run and exits, allowing the GHA runner to terminate immediately.

### 3. Deep Contact Enrichment
- **Functionality:**
  - In the Apify Actor configuration (`apify-enrichment.ts`), set `"scrapeCompanyWebsite": true`.
  - This tells Apify to find the venue's website and crawl it for `email`, `facebook`, `instagram`, and `linkedin`.
  - Map these extracted emails to the `venues.email` column. This is the crucial fuel for Phase 9/10 (Claim Your Listing).

---

## Technical Details

### Webhook Flow
1. GitHub Action runs `data-enrichment.ts`.
2. Script POSTs to Apify with a batch of 200 venues and the Webhook URL, then exits (0 seconds wait time).
3. Apify processes the 200 venues (takes ~10 minutes).
4. Apify POSTs to `https://api.kidspot.london/api/admin/webhooks/apify`.
5. KidSpot backend fetches the results from Apify and updates the database.

### Security
The webhook must not be open to the public. It will use a query parameter token (`?token=...`) that must match an environment variable on the server.

## Verification Plan
1.  **Local Tunnel Testing:** Use a tool like `ngrok` or `localtunnel` to expose the local backend to the internet temporarily. Trigger an Apify run pointing to the `ngrok` URL and verify the backend receives and processes the payload.
2.  **Email Verification:** Check the database after a successful webhook run to confirm that `email` fields are being populated for venues that have websites.
