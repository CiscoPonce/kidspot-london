# Plan 17-03: Scaling & Monitoring

## Objective
Ensure the new high-velocity Apify pipeline runs frequently enough to process the backlog of venues and provide visibility into its performance and API credit usage.

## Proposed Changes

### 1. GitHub Actions Workflow Configuration
- **Location:** `.github/workflows/data-enrichment.yml`
- **Action:** Verify and potentially increase the cron schedule frequency.
  - If the script processes 20 venues per run, running it every 4 hours yields 120 venues/day.
  - To hit the target velocity of 2,000+ venues/day, the workflow should either run more frequently (e.g., hourly) or the batch size in `enrichViaApify` should be increased (e.g., to 100 venues per run).
- **Environment:** Ensure `APIFY_API_TOKEN` is added as a repository secret.

### 2. Monitoring & Dashboard Updates
- **Location:** `backend/src/routes/admin.ts` (Enrichment Stats endpoint)
- **Action:** Update the `/api/admin/enrichment-stats` endpoint to track the success rate of the Apify pipeline specifically, if possible, or ensure the overall coverage metrics accurately reflect the new data influx.
- **Credit Tracking:** (Optional but recommended) Add a lightweight log or alert if the Apify run fails due to insufficient funds (e.g., HTTP 402 or specific JSON error response from Apify).

---

## Technical Details

### Batch Size vs. Frequency Strategy
Given the $5/month free tier (~10,000 venues/month):
- Target processing rate: ~330 venues/day.
- Ideal GHA configuration: Run every 4 hours (6 runs/day).
- Ideal batch size: 55 venues per run (6 * 55 = 330).

*Note: The script currently defaults to 20, which is extremely safe. We can scale the `batchSize` parameter passed in `data-enrichment.ts` up to 50 once the initial backlog is cleared.*

## Verification Plan
1.  **GHA Execution Check:** Verify the GitHub Actions logs after the next scheduled run to ensure the environment variables are correctly injected and the Apify layer executes.
2.  **Coverage Monitoring:** Monitor the output of the `/admin/enrichment-stats` endpoint over 48 hours to confirm the steady increase in Website and Phone coverage.
