# Plan 17-02: Pipeline Orchestration

## Objective
Integrate the new Apify enrichment script into the existing scheduled data enrichment pipeline, positioning it strategically to maximize data quality while minimizing API costs.

## Proposed Changes

### 1. Update `data-enrichment.ts`
- **Location:** `backend/scripts/discovery/data-enrichment.ts`
- **Functionality:**
  - Import the new `enrichViaApify` function from `apify-enrichment.ts`.
  - Inject it as **Layer 2** in the pipeline execution sequence.
  - Shift the existing `enrichViaWebScraping` (Brave Search) to **Layer 3** as a fallback for venues not found on Google Maps.

### 2. Pipeline Sequence
- **Layer 0:** Reverse-Geocoding (Address formatting and postcodes)
- **Layer 1:** OSM Contact Enrichment (Fast, free extraction from existing OpenStreetMap tags)
- **Layer 2: Apify Google Maps Enrichment** (High-accuracy extraction for top venues missing data)
- **Layer 3:** Web Scraper Fallback (Generic web search for any remaining missing fields)

---

## Technical Details

### Code Structure
```typescript
  // Layer 2: Apify Google Maps Enrichment
  try {
    console.log('═══ Layer 2: Apify Google Maps Enrichment ═══');
    const apifyResult = await enrichViaApify(20);
    results.apify = apifyResult;
    console.log(`  → ${apifyResult.enriched} enriched, ${apifyResult.skipped} skipped...`);
  } catch (error) {
    console.error('Layer 2 (Apify scraper) failed:', error);
  }
```

### Error Handling
- The pipeline must gracefully handle cases where the `APIFY_API_TOKEN` is missing, skipping Layer 2 and logging a warning, rather than crashing the entire pipeline.
- Network timeouts or Apify API rate limits must be caught and logged without disrupting Layer 3.
